# 0005. TypeScript для всего кода

**Статус:** принято · **Дата:** 2026-10-11

## Контекст

Проект переходит из состояния «один разработчик» в состояние «скоро будет команда». Написан на JavaScript без типов.

Главная проблема не в том, что код неправильный, а в том, что его **трудно понять**. При чтении JavaScript не видно, что функция принимает и что возвращает: это выясняется только чтением всех мест вызова. На домене вроде «уведомление → доставка → подписчик», где сущностей много и поля пересекаются, это особенно больно.

## Решение

Весь код — бэкенд и оба фронтенда — переводится на TypeScript со строгим режимом.

Дополнительно: типы контрактов API выносятся в отдельный пакет `packages/shared` и используются бэкендом, админкой и PWA.

## Последствия

**Хорошо:**
- Тип **является** документацией: читая сигнатуру, видно, что куда передаётся, без чтения тела функции
- Ошибка в контракте ловится при сборке, а не в проде — особенно ценно, когда бэкенд и два фронтенда развиваются вместе
- Автодополнение и подсказки в редакторе
- Рефакторинг без страха: переименовал поле — компилятор показал все места

**Плохо:**
- Время на перевод: аннотации типов, обёртки для Zod, настройка сборки
- Нужен `skipLibCheck` и допуски в сторонних типах, иначе сборка падает на чужих ошибках
- Часть ошибок проявится только при сборке — это непривычно по сравнению с запуском и падением в рантайме

## Почему именно `packages/shared`

Три потребителя одного контракта — идеальное условие для рассинхронизации: бэкенд меняет поле, фронтенд компилируется без ошибок и падает у пользователя.

Схема на Zod проверяется в рантайме и из неё выводится тип. Одно объявление — и валидация, и тип, и документация. Расхождение становится ошибкой компиляции.

## Отвергнуто

**Остаться на JavaScript с JSDoc.** Даёт подсказки без шага сборки. Но JSDoc не проверяется при компиляции: ошибка в типах обнаружится в рантайме, а JSDoc в проекте такого размера разъедется.

**Переводить постепенно.** Медленное, но безопаснее. Проблема в том, что проект и так переписывается ядром: два одновременных больших процесса (перевод типов и перенос на PostgreSQL-совместимую структуру) дадут двойную сложность на каждом шаге. Лучше один большой проход с ясной целью.

**JSDoc + `checkJs`.** Практически TypeScript без переписывания. Работает, но авторинг типов всё равно нужно вынести отдельно, и часть возможностей (перегрузки, generics) остаётся слабее.
