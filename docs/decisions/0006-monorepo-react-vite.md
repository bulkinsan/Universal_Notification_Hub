# 0006. Один репозиторий, React + Vite для обоих фронтендов

**Статус:** принято · **Дата:** 2026-10-11

## Контекст

Существуют два фронтенда: `admin/` (панель управления) и `pwa/` (клиент подписчика). Оба написаны на vanilla JavaScript без сборки, около 500 строк вместе.

Планируется, что админка станет существенно больше: роли, квоты, поиск по доставкам с фильтрами и разбивкой по страницам, графики, ручные повторы, управление ключами. Vanilla JavaScript на таком объёме потребует самописной таблицы, пагинации и состояния — то есть мы пишем с нуля то, что уже сделано и отлажено.

Решили оба фронтенда удалить и написать заново на React + Vite + TypeScript.

## Решение

- Один репозиторий: `backend/`, `admin/`, `pwa/`, `packages/shared/`
- Оба фронтенда — React + Vite + TypeScript
- Корневый `package.json` с рабочими областями, одна установка зависимостей и одна команда сборки

## Последствия

**Хорошо:**
- Готовые решения для таблиц с виртуализацией, фильтрами и разбивкой на страницы — вместо самописных
- Роли и права доступа описываются в одном месте на клиенте, а не в проверках `if` по всей разметке
- Общие компоненты между админкой и PWA: загрузка файлов, показ уведомления, оформление форм
- `packages/shared` рядом с бэкендом: изменение контракта ломает сборку всех трёх сразу
- Один клон репозитория и одна история — новый человек в команде получает всё сразу

**Плохо:**
- Появляется шаг сборки: фронтенты больше нельзя отдать как есть из корня бэкенда
- Три пакета в одном репозитории — больше настроек
- Нужен CI, который собирает всё, а не только гоняет тесты бэкенда

## Про сборку и развёртывание

Раньше бэкенд сам отдавал `/admin` и `/pwa` как статику. С новой схемой так не выйдет — это собранные файлы.

Два варианта:

- **Собирать фронтенды в CI и отдавать статикой** через Express. Один процесс раздаёт всё.
- **Раздавать готовую статику nginx.** Nginx и так нужен для TLS и статики, сервис не тащит файловую систему в рантайм.

Второй предпочтительнее для боевого сервера, первый удобнее для разработки. Решение принимается в Фазе 8 вместе с развёртыванием, [ADR-0004](0004-worker-as-separate-process.md) от него не зависит.

## Отвергнуто

**Отдельные репозитории.** Чище границы, но новый человек клонирует три репозитория, а изменение контракта расходится по трём веткам. Для команды это лишняя координация без выигрыша.

**Next.js.** Данные живут на сервере, а не в чужой базе. Рендеринг на сервере для админки, которая почти целиком работает с API, — лишний слой.

**Оставить vanilla JS.** Работает на текущем объёме. Но список возможностей админки (см. [архитектуру](../ARCHITECTURE.md)) — это десятки экранов с таблицами и фильтрами, и писать их без библиотек дольше, чем перейти на React.
