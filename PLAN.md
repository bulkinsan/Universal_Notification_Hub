## 1. Цель проекта

Универсальный бэкенд уведомлений (Universal Notification Hub).

- Сервисы-отправители (банки, соцсети и т.п.) шлют уведомления через REST API.
- Бэкенд доставляет их пользователям по подходящим каналам.
- Разные клиенты подключаются к бэкенду через API: веб (PWA), мобильные (iOS/Android, нативные), и др.
- Клиенты пишутся отдельно и по документации бэкенда.

```
Сервис-отправитель ──POST /api/v1/notify (X-API-Key)──>  Бэкенд  ──каналы──>  Клиенты
```

## 2. Архитектура (целевая)

```
                         ┌────────────────────────────────────────────┐
                         │                БЭКЕНД                      │
                         │  Node.js + Express + SQLite (→PG потом)    │
                         │                                            │
  Источник (банк,        │  POST /api/v1/notify  (X-API-Key)          │
  соцсеть)  ─────────────┼─►  принимает уведомление                  │
                         │                                            │
                         │  ФАН-АУТ (по подписчикам, по каналам):     │
                         │    • web    → Web Push (VAPID)             │
                         │    • mobile → WebSocket (планируется)      │
                         │                                            │
                         │  GET /api/v1/notifications?user_id=        │
                         │    история для клиентов (оффлайн-подтяжка) │
                         │                                            │
                         │  /api/v1/admin/* (JWT) — админка:          │
                         │    источники, API-ключи, статистика        │
                         └──────────────┬──────────────┬─────────────┘
                                        │              │
                    ──── Web Push ──────┘              └──── WebSocket ────
                              │                              │
                   ┌──────────▼────────┐          ┌──────────▼───────────┐
                   │  PWA (веб)        │          │  iOS / Android       │
                   │  /pwa (демо)      │          │  нативные клиенты    │
                   └───────────────────┘          └──────────────────────┘

   /admin (vanilla JS) — админский веб-фронт (JWT в localStorage)
```

## 3. Текущее состояние (на момент старта)

### Что уже есть
- **Бэкенд** `backend/` (Node.js + Express, БД SQLite через `sql.js`):
  - Источники: создание (выдаёт `api_key`), список, детали, обновление, загрузка логотипа.
  - Подписки: subscribe / unsubscribe / список подписок пользователя.
  - Уведомления: `POST /notify` с auth по `X-API-Key`, фан-аут по подписчикам, учёт доставок.
  - Канал доставки — только Web Push (VAPID).
  - Миграции: `backend/src/migrations/001_initial.sql`.
  - Таблицы: `traffic_sources`, `users`, `user_subscriptions`, `notifications`, `notification_deliveries`.
- **Клиент PWA** `pwa/` — демо: список источников, подписка, получение пушей (Service Worker). Отдаётся бэкендом на `/pwa`.
- **Конфиг** через `.env` (см. `.env.example`).

### Чего нет (предстоит сделать)
- Админ-доступ (авторизация, JWT) и админ-фронт.
- Механизмы безопасности (rate-limit, helmet, CORS, magic-bytes, валидация).
- Управление API-ключами (регенерация).
- Статистика и история уведомлений (admin API).
- История уведомлений для клиентов (`GET /notifications?user_id=`).
- WebSocket-канал (отложен на следующий этап).
- Тесты (юнит + API) и CI.
- Полная документация API.

## 4. Принятые решения (Q&A)

> **Внимание: часть решений ниже пересмотрена 2026-10-11.** Актуальные решения — в [`docs/decisions/`](docs/decisions/).
>
> | Тема | Тогда | Сейчас |
> |---|---|---|
> | Основа/стек | Node.js + Express + SQLite | Без изменений, но TypeScript ([ADR-0005](docs/decisions/0005-typescript.md)) |
> | База | SQLite через `sql.js` | Настоящий SQLite через `better-sqlite3`, Kysely ([ADR-0001](docs/decisions/0001-sqlite-first-postgres-later.md)) |
> | Очередь задач | Не предусмотрена | Очередь в базе, трёхстадийная раздача ([ADR-0002](docs/decisions/0002-database-backed-queue.md), [ADR-0003](docs/decisions/0003-two-stage-delivery.md)) |
> | Идентификация клиентов | Анонимный `user_id` в браузере | Учётные записи с входом ([ADR-0007](docs/decisions/0007-subscriber-accounts.md)) |
> | Админ-доступ | Один аккаунт, логин/пароль из env | Учётные записи сотрудников с ролями и журналом действий |
> | Админ-фронт | Vanilla JS, отдаётся бэкендом | React + Vite, отдельная сборка ([ADR-0006](docs/decisions/0006-monorepo-react-vite.md)) |
> | WebSocket | Отложен на следующий этап | Обязателен, Фаза 4 |
> | Каналы доставки | Web Push + WebSocket | Без изменений, плюс APNs/FCM для мобильных |
> | Тест-фреймворк | `node:test` | Без изменений |
> | CI | GitHub Actions | Без изменений, плюс сборка фронтендов и проверка типов |
> | Модель API отправки | `POST /notify` → фан-аут | `POST /notify` кладёт задачу в очередь и отвечает `202` |

Таблица ниже сохранена в исходном виде как часть истории проекта.

| Тема | Решение |
|------|---------|
| Основа/стек | Эволюционировать текущий: Node.js + Express + абстракция БД (SQLite сейчас, PostgreSQL потом) |
| Каналы доставки | Web Push (веб) + WebSocket (нативные iOS/Android) |
| WebSocket | **Отложен на следующий этап** (не в текущем объёме) |
| Идентификация клиентов | Анонимный `user_id` (клиент генерирует и хранит) |
| PWA-клиент | Оставить как демо-клиент, отдаётся бэкендом на `/pwa` |
| Модель API отправки | Один `POST /notify` → фан-аут по всем каналам (бэкенд решает) |
| Админ-доступ | Один админ-аккаунт (логин/пароль из env), JWT |
| Админ-фронт | Vanilla JS без сборки, папка `admin/`, отдаётся на `/admin` |
| Состав админки | CRUD источников + управление API-ключами + статистика/история |
| Тест-фреймворк | Встроенный `node:test` (ноль зависимостей) |
| CI | GitHub Actions — тесты/сборка при push и PR |
| Брокер сообщений (Kafka и т.п.) | Не нужен сейчас; при росте — между отправителями и хабом (Redis Streams/RabbitMQ), не трогая клиентов |

## 5. Полный план работ

### Фаза 1. Бэкенд: безопасность + полный API
- **1.1 Конфиг и зависимости** — `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `JWT_SECRET`, `JWT_EXPIRES_IN`, `CORS_ORIGINS` в `config.js` и `.env.example`; зависимости `jsonwebtoken`, `helmet`, `express-rate-limit`.
- **1.2 Мидлвары безопасности** — `helmet()`, отключить `X-Powered-By`; rate-limit на `login` и `notify`; настраиваемый CORS; валидация входных данных (sources, subscribe, notify).
- **1.3 Админ-аутентификация** — `POST /api/v1/admin/login` (timing-safe сравнение), `GET /api/v1/admin/me`, JWT-мидлварь `requireAdminAuth`; пароль только в env (dev-дефолт с автогенерацией).
- **1.4 Усиление существующего** — magic bytes для логотипов (JPEG/PNG/WebP), лимиты/типы по всем ручкам.
- **1.5 Admin API** — CRUD источников, вкл/выкл (`activate`/`deactivate`), логотип, регенерация API-ключа, статистика источника, история уведомлений и доставок, сводка.
- **1.6 Публичный API** — `GET /api/v1/notifications?user_id=` (история для клиентов).
- **1.7 Гигиена** — общий модуль миграций (из `server.js`/`migrate.js`), убрать дубль `sql.js`, центральный error-handler.
- **1.8 Рефакторинг под тесты** — вынести создание `app` из `listen`; поддержка in-memory БД в `db.js`.

### Фаза 2. Юнит-тесты (node:test)
- `auth`: `hashApiKey`, timing-safe сравнение.
- `logo`: валидация mime + magic bytes, лимит размера.
- `config`: дефолты/парсинг env.
- `delivery`: сборка payload'а web-push (мок `webpush`).

### Фаза 3. API/интеграционные тесты (node:test + fetch)
- Запуск `app` на случайном порту с in-memory БД.
- Флоу: создать источник → ключ → notify (мок доставки); subscribe/unsubscribe; история; админ-флоу (login, CRUD, регенерация ключа, статистика).
- Негативные: нет токена, неверный пароль, мусор в upload, невалидный `X-API-Key`.
- Структура: `backend/test/unit/`, `backend/test/api/`; скрипт `npm test` (юнит + API).

### Фаза 4. CI при сборке (GitHub Actions)
- `.github/workflows/ci.yml`: `checkout → setup-node → npm ci → npm test` на push и PR (ветки `dev`, `master`).

### Фаза 5. Документация (README)
- Полный контракт REST (публичный + админ), аутентификация (X-API-Key / JWT), коды ошибок, `curl`-примеры, инструкция запуска, раздел «WebSocket (планируется)».

### Фаза 6. Админ-фронт (vanilla JS, `/admin`)
- Логин (JWT в localStorage) → дашборд-сводка → CRUD источников, логотип, вкл/выкл → API-ключи (показать/регенерировать) → история уведомлений и доставок с фильтрами и CSS-барами.

### Верификация
`npm test` + ручной curl-прогон + проверка админки в браузере.
